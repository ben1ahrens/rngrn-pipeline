# C2 screening wave. Every arm is paired with c2_A_base400 on the SAME 8 seeds and the
# SAME targets, moving exactly ONE override. That pairing is also the no-op control: if an
# arm comes back bit-identical to the baseline, the knob is inert.
#
# TWO targets in the screen, and the reason is measured cost, not selection. nc1's training
# cost varies ~30x ACROSS TARGETS at identical settings: in c2_A_base400, sample_0000 and
# sample_0001 each completed 8 seeds in ~90 s (4 workers), while sample_0002 took >40 min
# for the same 8 seeds at 100 % CPU with a 2.4 s rollout -- i.e. the cost is in the training
# loop's steady-state solve, not in scoring. Screening on the two cheap targets buys ~7
# single-axis arms for the price of one arm on the expensive ones. The BASELINE and the
# CONFIRMATION cell both run all five targets; only the screen is narrowed, and the screen
# decides nothing on its own.
#
# sample_0000 and sample_0001 are also the right two to screen ON: 0000 is the hard control
# (scripts/c2_jacobian_probe.py measured its recovered J admitting NO Turing instability at
# any D over 400 draws, 4/4 seeds) and 0001 is the only baseline target with a Turing seed,
# so between them they bracket the boundary the screen is trying to move.
#
# workers 6, not 4: the bottleneck was measured to be CPU (the 4 workers sat at 100 % CPU
# with a 2.4 s GPU-side rollout), and 14 cores are available with unit C1 holding 3.
#
# Axes, and why each:
#   detach   loss.detach_xstar -- the one REAL behavioural difference between the library
#            and scripts/exp05_pixel_minibatch.py, which measured 36.8 % Turing. Its own
#            docstring records that it "has not been isolated in an A/B". This is that A/B.
#   dinit    model.d_init_from_kstar -- unit B4 measured the default theta_D init starting
#            29x TOO SMALL on the dimensional path, and D is what sets where sigma(k) peaks.
#   turing8  loss.weights.turing -- the baseline's sig_max_pos climbs -0.47 -> -0.07 and
#            then PLATEAUS with ~1e-4/step left (measured from the stored history arrays).
#            A plateau short of zero at full weight is a balance between terms, so the
#            weight is the knob that moves it. turing2 brackets it from below.
#   nostage  loss.staging_keys=[] -- the Turing term is at weight 0 for the first 25 % of
#            the budget and ramped over the next 25 %, so at 400 steps it is at full weight
#            for only half the run.
#   priorOFF loss.weights.param_prior=0 -- the CONTROL for criterion 3.4. Stage 0 measured,
#            for competitive, that the prior does NOT decide which targets pattern. Never
#            checked for nc1, which is the binding form.
#   hill3    model.n_hill -- fixed at 2 everywhere while gen_tg3.py draws n in {2,3,4}
#            (BIO_VIABILITY limitation 2). Never swept.
#   steps2000 the step axis, on the cheap targets, for the plateau curve.
c2_D_turing8|0,1,2,3,4,5,6,7|sample_0000,sample_0001|6|-o train.adam_steps=400 -o loss.weights.param_prior=1.0 -o loss.weights.turing=8.0
c2_C_dinit|0,1,2,3,4,5,6,7|sample_0000,sample_0001|6|-o train.adam_steps=400 -o loss.weights.param_prior=1.0 -o model.d_init_from_kstar=true
c2_F_priorOFF|0,1,2,3,4,5,6,7|sample_0000,sample_0001|6|-o train.adam_steps=400 -o loss.weights.param_prior=0.0
c2_B_detach|0,1,2,3,4,5,6,7|sample_0000,sample_0001|6|-o train.adam_steps=400 -o loss.weights.param_prior=1.0 -o loss.detach_xstar=true
c2_E_nostage|0,1,2,3,4,5,6,7|sample_0000,sample_0001|6|-o train.adam_steps=400 -o loss.weights.param_prior=1.0 -o loss.staging_keys=[]
c2_H_hill3|0,1,2,3,4,5,6,7|sample_0000,sample_0001|6|-o train.adam_steps=400 -o loss.weights.param_prior=1.0 -o model.n_hill=3
c2_I_turing2|0,1,2,3,4,5,6,7|sample_0000,sample_0001|6|-o train.adam_steps=400 -o loss.weights.param_prior=1.0 -o loss.weights.turing=2.0
c2_G_steps2000|0,1,2,3,4,5,6,7|sample_0000,sample_0001|6|-o train.adam_steps=2000 -o loss.weights.param_prior=1.0

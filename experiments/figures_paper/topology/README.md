# GRN topology + non-identifiability figures (paper claim 6)

Figures for the topology claim and the identifiability finding. Everything here is
regenerated by one script from run records that are already tracked in git.

## Headline

> **Across 26 seeds on 3 targets, 26/26 learned a distinct Jacobian sign structure.
> Sign recovery sits at chance (pooled median 0.333, uniform chance 0.333, and a
> constant "all-repressing" guess would score 0.444 — better than the median). The same
> models reproduce the phenotype: 19/20 Turing-converged runs pattern in rollout, and
> k\* is recovered to a 3.1–6.5 % median relative error.**
>
> The data supports recovery of a **dynamical equivalence class**, not of a unique
> topology. Every figure here is built to make that distinction impossible to miss.

## Firewall position

`make_topology_figures.py` is **scoring-side: it reads ground truth**
(`interaction_matrix`, `jacobian`, `D`, `x_star`, `params_json` out of `payload.h5`).
That is legal post-hoc reporting. Two deliberate choices keep it clean:

1. **It lives outside `scripts/`.** The suite and the notebooks put `scripts/` on
   `sys.path`, so a payload-reading module there is importable by bare top-level name and
   must be added to `tests/test_firewall.py::FORBIDDEN` (CLAUDE.md §5). This file is not
   importable that way, so **no `FORBIDDEN` entry is required or was added.**
2. **It imports no training code.** Only `rngrn.eval.topology.plot_topology` (a pure
   renderer of a model's own learned parameters) and `rngrn.scoring.permutation`
   (scoring-side by construction). Nothing from `model` / `recover` / `losses` / `train`.

## Two verifications worth recording

**Checkpoints agree with the JSON exactly.** The script reads learned parameters from
`results/train_results.json` (`recovered.*`) rather than `checkpoints/model.pt`, because
the checkpoint stores unconstrained `theta_*` that only `rngrn.model.RNGRN` can decode —
importing it would drag training code into this script for no gain. The two were checked:
decoding all 10 D5 checkpoints through `RNGRN` and comparing `KA, KR, alpha, beta, delta,
D` against the JSON gave a **maximum relative discrepancy of 0.0**.

**The stored permutations were not trusted.** Every run record has
`n_permutations_searched: 1` (identity only), so the search was re-run from scratch in
both modes — pinned (`free_observed=False`) and the full 6 (`free_observed=True`). The
re-run pinned score reproduces the stored `sign_match_frac` exactly for all 26 runs.

## The one caveat that must travel with the 6-permutation numbers

**Every run here is fully observed (N = m = 3, `observed_idx=[0,1,2]`).** The gate
therefore pins *every* channel, so the admissible permutation set has exactly **1**
element and the identity is the only legitimate labelling. `align_permutation`'s
`free_observed=True` mode enumerates all 6 by discarding that known correspondence; its
module docstring says such a score "is an upper bound and must be reported as such". So:

* **Headline number = the pinned score** (identical to the pipeline's `sign_match_frac`).
* The 6-permutation score appears only in fig3/fig3b, always **labelled an upper bound**
  and always **printed next to the pinned score**.

Reporting the 6-perm number alone would inflate the median from 0.333 to ~0.67.
